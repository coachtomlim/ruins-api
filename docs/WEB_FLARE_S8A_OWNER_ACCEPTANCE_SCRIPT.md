# WEB-FLARE S8A Owner Acceptance Script

Use only after Codex returns a complete local/browser PASS and before public deployment approval.

## First-time receiver check

Open the S8A receiver in a portrait phone viewport without prior explanation.

Confirm that within a few seconds the screen communicates:

- this is Dungeon Runner;
- a friend challenged the receiver;
- the Hero must reach the EXIT;
- the target finishing HP is obvious;
- the goal is precision, not killing the Hero;
- closer to target means higher score and more Gold;
- Accept Challenge is the dominant action.

If any of those require scrolling or careful reading, REVISE.

## Dungeon choice check

After Accept:

- one dungeon is visible at a time;
- swipe/arrows are obvious;
- target remains visible;
- `USE THIS DUNGEON` is dominant;
- `CUSTOMIZE - OPTIONAL` is clearly secondary;
- no customization is required to continue.

## Customization check

Open optional customization:

- MONSTERS / TRAPS / SUPPORTS behave as panels, not a long form;
- budget remains visible;
- control labels are readable;
- `DONE` is easy to find;
- no accidental over-budget run is allowed.

## Run check

Start the Hero:

- movement/combat animations are visible;
- Pause/Resume works;
- Overview materially zooms/reframes to show the dungeon;
- control changes to Follow Hero;
- Follow Hero visibly restores tracked camera.

## Reward check

At completion:

- battlefield is replaced by a dedicated result/reward panel;
- target and actual finish are clear;
- score is clear;
- friend's Hero Gold and receiver Builder Gold are separate;
- failed clear shows zero Builder Gold;
- reward ownership cannot be mistaken.

## Continuation check

- `RUN AGAIN` repeats the same build/result deterministically.
- `EDIT THIS DUNGEON` returns with current room/options preserved.
- `SAVE THIS GOAL & BUILD YOUR OWN` opens a dedicated account-registration panel.
- that panel never routes to Buddy/Test and states that nothing has been saved yet.

## Decision

PASS only if the experience feels playable on a phone without explanation and the core mission/reward loop is understandable immediately.
